## Konvensi & pola yang perlu dikenali

- **View didefinisikan di Python** (`get_view` override mengembalikan arch XML string, contoh <Src file="mayapada/models/hospital.py" line={52} symbol="get_view" />; ±146 override di modul ini) untuk banyak model master — XML view di `data/` tidak selalu menjadi sumber tampilan.
- **Field sync** (`sync_type`, `sync_id`, `sync_id_api`, `sync_consol_*`) dideklarasikan sekali di <Src file="mayapada/models/sync.py" /> lalu di-*assign* ke banyak model.
- **SQL langsung** banyak dipakai untuk performa (upsert, laporan, view jurnal). Constraint ORM tidak melindungi jalur ini.
- **Hard-coded**: nama company (Bogor, Tangerang), kode akun (`1104020101`, `2103000000`, `2103030000`, `7999000000`), nama item/service di fee dokter, nama kategori "Medical Equipment".
- **Sisa Python 2** (`unicode`, `xrange`) di jalur sync lama.
- **Logging ke file** di `/opt/odoo16/logs/` dari dalam method bisnis.
- Instruksi proyek (`AGENTS.md`): perubahan Odoo dibatasi pada file `eproc_tc` kecuali diminta; server adalah sumber kebenaran; repo bisa tertinggal dari server.

## Cara menelusuri sebuah proses

1. Mulai dari **menu** (`eproc/eproc_tc_menu.xml`, `data/menu.xml`) → action → model.
2. Cari `state = fields.Selection` untuk lifecycle; cari `def action_` untuk tombol.
3. Cari pemanggilan `account.move` `create` untuk dampak akuntansi.
4. Cari nama tabel Bridge (`trx_*`, `mst_*`) di README Airflow untuk asal data.
5. Cek project memory untuk perbedaan server vs repo.
